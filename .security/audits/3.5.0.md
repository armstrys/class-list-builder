## Vulnerability Findings

No security findings.

The one thing worth stating explicitly, because "a full-screen overlay" reads
like an interaction guard in a diff: **the scrim is not one.** It is
`pointer-events: none`, so it cannot intercept a click, and it renders below the
callout in z-order. This is deliberate — the tour is non-modal by design, and a
teacher must remain able to operate the very control a step is pointing at. A
test asserts the `pointer-events: none` rule and the z-index ordering, so a
future edit cannot quietly convert the tour into a click trap.

A step may also have more than one anchor. "Save and load" names `data-tour="save"`,
which sits on Save Project — a control that only renders once students exist. Load
Project, next to it, is always rendered, so it carries the same attribute as a
fallback and the lookup takes the first anchor that actually has client rects.
Without this, a first-time user pressing `?` on an empty roster got the docked
corner instead of a callout attached to the header.

The scrim is painted with `box-shadow: 0 0 0 100vmax` on a transparent element
whose geometry comes from `getBoundingClientRect()` of an app element. No value
from it is interpolated into markup, written to storage, or sent anywhere; the
only style consumer is `React` style objects with numeric px values.

For completeness, the two informational findings from v3.3.0 remain accurate
against the current tree: values are rendered only through React text
interpolation (no `dangerouslySetInnerHTML` / `innerHTML` / `eval` /
`new Function` anywhere in `src/`), and no student data is written to
localStorage.
