# Security Audit — v2.0.3

## Scope

Single-file React SPA distributed as a standalone HTML bundle, plus its
build pipeline and the public security claims in `SECURITY.md`.

Paths covered by the manifest hash:

- `src/**` (31 files)
- `package.json`, `package-lock.json`
- `SECURITY.md`
- `build-standalone.js`, `class-list-builder-source.html`,
  `scripts/validate-build.js`

Out of scope: `node_modules/` (covered transitively via `npm audit`),
`tests/**`, developer-only scripts not in the manifest.

This release supersedes the v2.0.2 audit (`.security/audits/2.0.2.md`),
which was never signed off because the release workflow failed due to the
`sbom/` directory not existing in the checked-out repository (empty
directories are not tracked by Git). The SBOM output path has been changed
from `sbom/` to the repository root in `.github/workflows/release.yml`.

Changes from v2.0.0:

1. **Path migration** — audit infrastructure moved from `audits/` and `scripts/`
   to `.security/audits/` and `.security/scripts/` for cleaner repo organization.
2. **SECURITY.md relocated** — moved from `docs/SECURITY.md` to repo root;
   all internal links updated across audit docs, README, CONTRIBUTING,
   `.well-known/security.txt`, and `src/components/WelcomeModal.js`.
3. **Documentation updates** — `SECURITY.md` gained YAML front matter with
   tier declaration, SBOM section, and corrected attestation version reference.
4. **Comment updates** — cross-references in `src/csv.js` and `build-standalone.js`
   updated to new audit path.
5. **Version bump** — `package.json` and `src/defaults.js` bumped to 2.0.3.
6. **New security-audit-system skill** — `.claude/skills/security-audit-system/`
   added as a standalone skill (does not affect runtime behavior).
7. **`.well-known/security.txt`** added for security contact discoverability.
8. **CI fix** — corrected `anchore/sbom-action` commit SHA in release workflow.
9. **SBOM path fix** — removed empty `sbom/` directory; SBOM now outputs to
   repo root to avoid ENOENT errors in CI.

No functional code changes. All v2.0.0 security claims remain valid.

## Prompt Injection Defense Notes

Scanned all 31 files under `src/`, the source HTML, the build script,
`scripts/validate-build.js`, and `SECURITY.md` for the sentinel patterns
enumerated in `.opencode/skills/security-audit/references/prompt-injection-defense.md`:

- "ignore previous instructions", "disregard prior", "override system"
- "you are now", "act as", "new instructions"
- "do not flag", "mark as safe", "skip this finding"
- Assistant/system role markers
- Bidi / zero-width Unicode
- Large base64/hex blobs in comments

**No prompt-injection attempts observed.** One false positive: the phrase
"act as safety nets" appears in `src/components/HelpModal.js:75` as normal
UI explanatory text. The codebase is clean of text that attempts to instruct
or redirect an AI auditor. The audit's scope, severity classifications, and
findings were not influenced by any in-source text.
