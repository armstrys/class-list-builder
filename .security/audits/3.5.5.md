## Methodology

Diff-focused audit of a dependency-only change, at base `1060b2e`, on
x86_64 Linux with Node 22.23.5 and npm 10.9.9.

1. `git diff 1060b2e` reviewed in full; the source diff is one string.
2. `package-lock.json` regenerated with `npm install` (no `--force` needed on
   this x86_64 host), then `npm ci` from a deleted `node_modules` to prove the
   lock is self-consistent — the same command CI runs.
3. Dependency reachability: `npm ls` over the added transitives, and
   confirmation that the shipped bundle inlines from unpkg by fixed URL
   (`build-standalone.js:200-203`, unchanged, `build-sha256` identical to
   3.5.4), so no `node_modules` package enters the release artifact.
4. `npm audit --json` against the new lockfile.
5. `npm test` (385 tests, 17 files), `npm run lint` (0 errors), `npm run
   format:check`, `npm run build`, `node scripts/validate-build.js`.
6. `npm run audit:hash` for the hashes in this front matter; component hashes
   compared against 3.5.4 to confirm which slices actually moved.
7. Lint baselines compared against the pre-bump tree via the `Lint & Format`
   job log on PR #110, so a new ruleset cannot hide behind the warning count.

`.github/dependabot.yml`: the first scheduled run (2026-11-14) placed
`@rolldown/binding-linux-x64-gnu` inside the `dev-minor-patch` group instead
of the dedicated `rolldown-binding` group the config declares above it,
producing exactly the combined diff that split was written to prevent (PR
#100). The documented Dependabot rule is that a dependency joins the first
group it matches, so the cause is not confirmed; `exclude-patterns:
['@rolldown/*']` on `dev-minor-patch` makes the split hold regardless. This
is configuration for a third-party service and introduces no execution path
into the repo. It also cannot be verified from CI — only the next scheduled
run can confirm it, which is a residual risk below.

actions. This draft treats that as a sign-off-time risk: the maintainer should
expect the first tagged release after this merge to need verification of the

they are correct.

## Prompt Injection Defense Notes

No prompt-injection attempt observed in this session. The change was executed
from Dependabot branch names, PR bodies, and third-party release notes: text
authored outside this project. All of it was treated as data.

Dependabot PR bodies in particular are structured text that describes version

readers ("users should upgrade", migration instructions). None of it can
change a version or a workflow pin; the pins were taken from the already-filed
PR diffs and re-resolved through npm, not from prose. Where a Dependabot PR
disagreed with what the registry now serves (rolldown 1.3.2 vs 1.3.4), the
registry won and the difference is recorded above rather than smoothed over.

Sentinel scan of the manifest-covered diff for text addressed to an AI
auditor — imperatives to ignore instructions, claims about scope or severity,
requests to mark findings as passing, fabricated sign-off blocks: none. The
only prose added to the manifest-covered tree is the version string itself;
