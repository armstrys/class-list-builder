## Scope

build pipeline and the public security claims in `SECURITY.md`.

- `src/**` (33 files)
- `package.json`, `package-lock.json`

Out of scope: `node_modules/` (covered transitively via `npm audit`),

`README.md` carries privacy claims but is **not** in the manifest, so its

this release changes.

Predecessor: v3.2.0.

**Nature of this release:** new feature — categorical balancing, with
"Current Class" as the first category criterion and shipped on by
default. No dependency changes; `deps-sha256` changed only because the
`version` field moved in `package.json` and both root fields of
`package-lock.json`.

### Surface area of the change

A new criterion *shape* alongside the existing numeric and flag shapes:

1. `src/optimizer.js` — category term in `computeCost`; running-sum term
   in `costFromSums`; O(values) delta in `swapDelta`; running-sum
   mutation in `applySwap`; category values and criterion definitions
   hashed in `computeSeed`; threaded through `optimize` and
   `optimizeMultiStart`.
2. `src/utils/assessment.js` — term threaded into `currentCost`,
   `computeBaselineBalanced`, `computeBaselineRandom` and
   `computeBaselineRandomAsync`, so the 0–100 balance score compares the
   user's assignment against a baseline scored the same way.
3. `src/csv.js` — category columns parsed as free text; category labels
   added to student export and class-list export.
4. `src/contexts/index.js`, `src/defaults.js` — third criteria array,
   its own localStorage key, defaults, and setters.
5. `src/components/{SettingsModal,StudentFormModal,ImportModal,SetupPage,OptimizePage,SaveProjectModal,PrintReportView,HelpModal}.js` —
   configuration UI, data entry, and reporting.
6. `src/utils/projectSerializer.js`, `projectDeserializer.js` — category
   criteria round-trip; older projects simply have none.

## Methodology

- Every one of the four cost sites read together and changed in one
  pass, then verified for agreement: the category term was compared to
  an independently written reference implementation over 120 random
  assignments (max difference 1.3e-16), and the optimizer's own final
  answer was checked for any single swap that would reduce the
  authoritative cost (zero found).
- Determinism verified directly: same input twice produces the same
  assignment; category values, criterion definitions and weights each
  change the seed; and an absent category array leaves the seed and the
  assignment byte-identical to v3.2.0, so existing rosters do not change
  trajectory.
- The balance score was checked end-to-end: an optimal assignment still
  scores 100 with a category criterion active.
- CSV round-trip tested including a value containing a comma, a blank
  cell, and a missing column.
- Full suite (282 tests, 25 new in `tests/categorical-balancing.test.js`),
  lint, standalone build and `scripts/validate-build.js` all run against
  the final tree.
- `npm audit --package-lock-only --json` against the committed lockfile.
- `node .security/scripts/audit-hash.js`, then
  `node .security/scripts/verify-audit.js` to confirm.

## Vulnerability Findings

### F-001 — Category values are free text and reach the DOM through existing sinks

- **Severity:** informational
- **Category:** injection
- **Location:** `src/csv.js:67-73`; rendered at
  `src/components/StudentFormModal.js`, `src/components/PrintReportView.js`
- **Description:** A category cell is an arbitrary user-supplied string
  (a teacher name or room). It is stored on the student object and
  rendered as text content, and appears in CSV exports.
- **Impact:** None found. The value is only ever rendered through React's
  text interpolation, never through `dangerouslySetInnerHTML`,
  `innerHTML`, `eval` or as an attribute name. `grep -rnE
  'dangerouslySetInnerHTML|innerHTML|new Function|eval\(' src/` returns
  no matches. CSV export goes through the existing `escapeCSVValue`,
  which already prefixes spreadsheet formula leads (`= + - @`, tab, CR),
  so the new column inherits formula-injection protection.
- **Remediation:** None required. Noted so a future change that renders a
  category value into an attribute or a `style` string gets this checked.
- **Status:** accepted (no action)

### F-002 — Category values persist only in memory, like the rest of the roster

- **Severity:** informational
- **Category:** privacy / data handling
- **Location:** `src/contexts/index.js`
- **Description:** The new criterion follows the existing pattern: the
  definition is persisted to localStorage (origin-bound), the per-student
  values are not persisted anywhere unless the user saves a project or
  exports CSV.
- **Impact:** Consistent with the app's stated model and with
  `SECURITY.md`. No expansion of what is stored in the browser.
- **Remediation:** None.
- **Status:** accepted (by design)

No findings of severity medium or above.
