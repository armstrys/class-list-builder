## Vulnerability Findings

No security findings.

Two things are worth stating explicitly because a diff-reader could otherwise
read them as security-relevant:

**The confirmation dialog is a UX gate, not an access control.** It reuses
`Modal`, so it inherits the shared focus trap, `aria-modal`, Escape handling
and the portalled-to-`<body>` render that keeps it announced to assistive tech.
It protects nothing: skipping the demo button simply closes the splash and
records the seen flag. It creates no privilege, grants no capability, and holds
no state that outlives the click. No security property depends on it.

**`DEFAULT_SAMPLE_COUNT` does not change what is generated.** The constant is
`100`, equal to both literals it replaced, so `generateSampleStudents` receives
the same argument as in v3.5.0. The change removes a drift hazard in the splash
copy, not a behavior. The count is only ever passed to a pure in-memory
generator and is not persisted, exported, or transmitted.

**No user-controlled value reaches a new sink.** The only DOM write introduced
is React text interpolation of static strings (`'Skip the demo?'`, `'Show me the
demo'`, `'❓'`, `'Take a tour'`). The tour's `querySelectorAll` in `src/components/Tour.js`
interpolates a target name drawn from the module-constant `TOUR_STEPS`, not from
user input, storage, or a URL parameter; it cannot select outside that fixed
list. The welcome/skip gates read `?welcome=1` and `?skipwelcome=1` from the URL,
which is unchanged from v3.3.0 and only toggles visibility of a static dialog.

For completeness, the informational notes from prior audits still hold against
this tree: no `dangerouslySetInnerHTML` / `innerHTML` / `eval` / `new Function`
anywhere in `src/` (grep returns no matches), and no student data is written to
localStorage.
