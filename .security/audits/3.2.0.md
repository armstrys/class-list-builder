# Security Audit — v3.2.0

## Scope

Single-file React SPA distributed as a standalone HTML bundle, plus its
build pipeline and the public security claims in `SECURITY.md`.

Paths covered by the manifest hash:

- `src/**` (33 files)
- `package.json`, `package-lock.json`
- `SECURITY.md`
- `build-standalone.js`, `class-list-builder-source.html`,
  `scripts/validate-build.js`

Out of scope: `node_modules/` (covered transitively via `npm audit`),
`tests/**`, developer-only scripts not in the manifest, and the new
`PRODUCT.md` / `DESIGN.md` / `.impeccable/design.json` documentation
files (prose only, not shipped in the bundle).

Predecessor: v3.1.1.

**Nature of this release:** accessibility and UI-quality pass. No
dependency changes and no runtime dependency added. `deps-sha256`
changed only because `package.json`'s `version` field changed;
`package-lock.json` is byte-identical to v3.1.1. `claims-sha256` is
unchanged because `SECURITY.md` is untouched.

Changed surfaces and why they were audited:

1. `Modal.js` — dialog now renders via `ReactDOM.createPortal` to
   `document.body`; `aria-hidden` scoping narrowed to `#root`.
2. `LoadProjectModal.js`, `SampleDataDialog.js` — hand-rolled
   `.modal-overlay` divs replaced by the shared `Modal`.
3. `StudentCard.js`, `StudentDetailModal.js` — keyboard-accessible path
   for moving a student between classes, including a new `<select>`.
4. `contexts/index.js` — class-count changes no longer wipe assignments
   unless the new count actually invalidates one; snapshot is pushed
   for undo first.
5. `app.js` — `beforeunload` guard while the roster is non-empty.
6. `OptimizePage.js`, `ClassColumn.js`, `SetupPage.js` — live region,
   ARIA labelling, transform-based animation, dead prop removal.
7. `styles.css` — eight previously undefined custom properties
   declared, contrast raised, focus ring, responsive breakpoints,
   reduced-motion support.

## Methodology

- `git diff main -- src/` read hunk by hunk, then each modified file
  read in full for surrounding context.
- Every new DOM attribute treated as a potential sink and traced back to
  its data origin (CSV import, project deserialization, sample data).
- Static sink sweep over the whole of `src/` for network, storage,
  script-execution, and HTML-injection primitives.
- CSP and the HTML entry diffed against `main` to confirm no policy
  change was required or made.
- Full suite (257 tests, including 32 new assertions guarding the
  specific regressions this release fixes), lint, standalone build, and
  `scripts/validate-build.js` (which parses the real bundled JSX with
  acorn-jsx) all run against the final tree.
- `npm audit --package-lock-only --json` run against the committed
  lockfile.
- `node .security/scripts/audit-hash.js` run after the last source edit,
  then `node .security/scripts/verify-audit.js` to confirm.

## Vulnerability Findings

### F-001 — `var()` references with no declaration silently painted surfaces transparent

- **Severity:** medium (operational, not attacker-facing)
- **Category:** other (UI integrity / legibility)
- **Location:** `src/styles.css:1-60`; call sites at
  `src/components/LoadProjectModal.js:155,159,297,347,351`,
  `src/components/ViolationsModal.js:227`,
  `src/components/constraints/OutOfClassTab.js:113`,
  `src/components/constraints/StudentMultiselect.js:34`,
  `src/components/constraints/ApartTab.js:185`,
  `src/components/SaveProjectModal.js:134,168,170`
- **Description:** Eight custom properties (`--warning`, `--error`,
  `--success`, `--text1`, `--bg1`, `--bg2`, `--primary`, `--radius-md`)
  were referenced but never declared. An undefined `var()` resolves to
  the guaranteed-invalid value, so the declaration is dropped. Where
  the pattern was `background: var(--warning); color: 'white'` this
  produced white text on a transparent background.
- **Impact:** The load-project overwrite confirmation — the single most
  safety-critical dialog in the app, the one that guards against
  destroying a saved project — lost its warning border, its heading
  colour, and its panel background at exactly the moment it needed to
  read as a warning. Constraint badges ("Keep Out of Class",
  "Already blocked") were illegible. No confidentiality or integrity
  impact; this is a legibility and error-prevention defect.
- **Remediation:** Declared all eight as aliases of the existing palette
  in `:root` (and rely on the alias chain for dark mode), and added a
  test that fails if any bare `var(--token)` reference lacks a
  declaration.
- **Status:** fixed-in-this-release

### F-002 — Every dialog was hidden from assistive technology

- **Severity:** medium (accessibility)
- **Category:** other (accessibility regression, pre-existing)
- **Location:** `src/components/Modal.js:56-63` (pre-fix)
- **Description:** `Modal` set `aria-hidden="true"` on `#root` while
  rendering the dialog **inside** `#root` (no portal; the only
  `createPortal` in the tree was in `PrintReportView.js`). A dialog
  inside an `aria-hidden` subtree is removed from the accessibility
  tree even though it carries `role="dialog"` and `aria-modal="true"`.
- **Impact:** Screen-reader users could focus controls in Settings,
  Student Detail, Constraints, Assessment, Violations, Help and Welcome
  that announced nothing — effectively trapping them in a silent
  region. No data exposure; a complete loss of access for one user
  population.
- **Remediation:** Dialog renders via `ReactDOM.createPortal` to
  `document.body`; `aria-hidden` is now applied to `#root` only and no
  longer falls back to `document.body` (which would hide the portal
  too). Both facts are asserted by tests.
- **Status:** fixed-in-this-release

### F-003 — Only mouse and HTML5 drag-and-drop could assign a student to a class

- **Severity:** medium (accessibility)
- **Category:** other (accessibility regression, pre-existing)
- **Location:** `src/components/StudentCard.js:40-46`,
  `src/components/ClassColumn.js:59-67`,
  `src/components/OptimizePage.js:172-184` (pre-fix)
- **Description:** The product's single core action — placing a student
  in a class — existed only as HTML5 DnD on plain `div` elements with
  no `tabIndex`, no `role`, and no `onKeyDown`. There was no touch path
  and no alternative assignment control.
- **Impact:** Keyboard-only and touch users could not complete the task
  at all. No security impact; total functional exclusion.
- **Remediation:** The card is now `role="button" tabIndex={0}` and
  opens the detail dialog on Enter/Space; that dialog gains a class
  `<select>` writing a numeric index. Drag-and-drop is retained, so
  this is additive. Because `setAssignment` in this app is the
  undo-wrapped setter, moves made this way remain reversible.
- **Status:** fixed-in-this-release

### F-004 — Editing the class count destroyed assignments without confirmation or undo

- **Severity:** medium (data loss)
- **Category:** other (data integrity)
- **Location:** `src/contexts/index.js:261-278` (pre-fix),
  called per keystroke from `src/components/SetupPage.js:66-73`
- **Description:** `syncTeachers` fires on every keystroke of the class
  count field and called `clearAssignmentsForClassCountChange`, which
  invoked the **raw** `setAssignment({})` — no undo snapshot — whenever
  *any* assignment existed. Typing a count from 3 to 30 passed through
  intermediate values and wiped the board mid-typing.
- **Impact:** Silent loss of the user's working arrangement, which for a
  full roster represents hours of work. Recoverable only by a full
  re-optimize, which discards manual placements.
- **Remediation:** The function now clears only when the new class
  count actually invalidates an existing assignment
  (`classIdx >= numClasses`), and pushes an undo snapshot before
  clearing. Growing the count, or shrinking it to a range that still
  contains every assignment, preserves the board.
- **Status:** fixed-in-this-release

### F-005 — Nothing survived a reload or tab close

- **Severity:** low (data loss)
- **Category:** other (data integrity)
- **Location:** `src/app.js` (no `beforeunload` in the tree before this
  release); state is memory-only in `src/contexts/index.js:19-28`
- **Description:** Students, assignments and locks were held only in
  React state. Only criteria and theme were persisted.
- **Impact:** A stray Cmd+W or accidental refresh destroyed the whole
  session with no warning.
- **Remediation:** A `beforeunload` guard is registered while
  `students.length > 0`, removed on cleanup. Browsers control the copy
  and may ignore it; it is a mitigation, not a save.
- **Status:** fixed-in-this-release

### F-006 — Dropping a student into a forbidden class succeeded silently

- **Severity:** low (correctness)
- **Category:** other
- **Location:** `src/components/OptimizePage.js:177-184` (pre-fix)
- **Description:** `handleDrop` wrote the assignment without consulting
  `keepOutOfClass`, so a teacher could manually place a student into the
  exact class a constraint forbids, with no feedback at drop time.
- **Impact:** The tool appeared to accept an invalid placement; the
  violation only surfaced later in the violation count. No security
  impact.
- **Remediation:** Not enforced at drop (the optimizer's penalty
  weights, not hard rejection, are the app's model — and silently
  refusing a deliberate manual move would be worse). Instead the
  violation count is now announced through a live region, so the
  illegal placement is reported immediately rather than remaining
  visually-only.
- **Status:** accepted as designed; feedback added
