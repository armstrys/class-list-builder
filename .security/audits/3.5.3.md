# Security Audit — v3.5.3

## Scope

Single-file React SPA distributed as a standalone HTML bundle, plus its
build pipeline and the public security claims in `SECURITY.md`.

Paths covered by the manifest hash:

- `src/**`
- `package.json`, `package-lock.json`
- `SECURITY.md`
- `build-standalone.js`, `class-list-builder-source.html`,
  `scripts/validate-build.js`

Out of scope: `node_modules/` (covered transitively via `npm audit`),
`tests/**`, developer-only scripts not in the manifest.

This release adds a display-only surface. The manifest-covered changes are
`src/optimizer.js` (cost model split into `computeCostTerms` with `computeCost`
as its ordered sum), `src/utils/assessment.js` (terms carried on the
assessment result, new `rankCostTerms`), `src/components/AssessmentModal.js`
and the new `src/components/ScoreBreakdown.js` (the rendered breakdown),
`.eslintrc.json`-adjacent globals, the new script tag in
`class-list-builder-source.html`, and the 3.5.3 patch version bump. The audit is
diff-focused: the touched modules were re-read in full, and the unchanged tree
relies on the v3.5.2 audit at `8eb9a09`.

This PR also adds `.github/dependabot.yml`, a Dependabot config for weekly
grouped version updates. `.github/**` is not in the manifest, so the addition
sits outside every audited hash: `manifest-sha256` is `sha256:e11a3daf…` with
and without it, and it touches no source, dependency, claim, or build file.

## Methodology

- `npm audit --json` reviewed against the current lockfile; summary below.
- The full diff read, then the touched modules re-read in their entirety
  (`src/optimizer.js`, `src/utils/assessment.js`,
  `src/components/AssessmentModal.js`, `src/components/ScoreBreakdown.js`),
  not just the changed hunks.
- Every claim in `SECURITY.md` verified by command or by reading the cited
  code path; results recorded in the table below.
- The release artifact was built and inspected: remote resource loads,
  outbound anchors and their `rel`/`target`, inline event handlers, CSP bytes.
- The new arithmetic was checked for the two failure modes that would matter
  here — a term array that could carry `NaN` into the rendered percentages, and
  a percentage that could disagree with the score it explains. Neither is
  reachable: `rankCostTerms` divides only when the total is `> 0` and drops
  non-positive terms first (`src/utils/assessment.js:354-370`), and
  `computeCost` is now literally the ordered sum of the same terms the UI is
  handed (`src/optimizer.js:242-247`), so the parts cannot drift from the
  whole.
- Sentinel scan of the changed files for text addressed to an AI auditor.

## Vulnerability Findings

No security findings of severity low or above.

The change is additive display logic on a number the app already computes, and
three things were checked because a diff-reader could reasonably want them
settled:

**The breakdown introduces no new sink.** `src/components/ScoreBreakdown.js`
renders React text nodes and inline `style` objects built from numbers
(`width: ${Math.max(2, percent)}%`). There is no `dangerouslySetInnerHTML`,
`innerHTML`, `eval`, or `new Function` anywhere in `src/` (grep returns no
matches), so term labels, which originate from user-typed criterion names,
reach the DOM as escaped text.

**The share bar is presentation, not data flow.** The bar's width is
`Math.max(2, percent)` percent of a fixed-width track; `percent` is an integer
in `0…100` produced by `rankCostTerms`. Nothing from the bar is written back to
state, storage, or the optimizer, so a rounding artifact cannot alter a score.

**`computeCost` and the displayed breakdown cannot disagree.** The refactor
keeps one implementation: `computeCostTerms` holds the math and
`computeCost` sums its output in the same order as before
(`src/optimizer.js:50-247`). Equivalence was established empirically as well —
300 randomized rosters across four argument shapes (1,200 cases, including
empty and zero-variance criteria) produced `Object.is`-identical totals between
the pre-refactor and post-refactor `computeCost`, with no `NaN` in any term —
and is covered by `tests/cost-breakdown.test.js`. The all-337 pre-existing test
assertions pass unchanged, which is the strongest available evidence that no
cost moved.

For completeness, the standing informational notes still hold against this
tree: no inline `on*=` handlers in the built artifact; no student data in
localStorage; no network calls in `src/`.
