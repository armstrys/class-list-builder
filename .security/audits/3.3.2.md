# Security Audit — v3.3.2

## Scope

build pipeline and the public security claims in `SECURITY.md`.

Paths covered by the manifest hash:

- `src/**` (33 files)
- `package.json`, `package-lock.json`
- `SECURITY.md`
- `build-standalone.js`, `class-list-builder-source.html`,

Out of scope: `node_modules/` (covered transitively via `npm audit`),
`tests/**`, developer-only scripts not in the manifest, and
`README.md` / `PRODUCT.md` / `DESIGN.md` / `.impeccable/design.json`.

Predecessor: v3.3.1.

**Nature of this release:** dependency-only patch. The only source change
is the `APP_VERSION` string in `src/defaults.js`. `sources-sha256` is
therefore unchanged from v3.3.1 except for that one value.

This release supersedes Dependabot PR #86, whose lockfile was based on
`main` at v3.1.1 and could not be merged as-is without reverting
everything since. The same two version bumps were applied to the current
lockfile instead.

### Dependency changes

| Package | From | To | Advisory resolved |
|---|---|---|---|
| `brace-expansion` | 1.1.18 | **1.1.21** | GHSA-q2hr-2g5m-vwhr — quadratic-time expansion of the `{a,b}` rewrite causes CPU denial of service (advisory severity: moderate) |
| `js-yaml` | 4.3.1 | **4.3.2** | GHSA-2883-xcg3-v3hh — `maxTotalMergeKeys` does not limit CPU use for empty merge sources (CVSS 7.5, high) |

Both are patch-level bumps. Neither changes a major version.

## Methodology

- The lockfile was edited in place from the v3.3.1 state, changing only
  the two package entries (version, resolved URL, integrity hash) and the
  two root `version` fields. `git diff` confirms 10 changed lines and
  nothing else.
- The exact `resolved` URLs and `integrity` hashes were taken from the
  Dependabot branch, whose lockfile had already validated them, rather
  than re-resolved from a macOS host. The repo pins
  `@rolldown/binding-linux-x64-gnu`, so a local regenerate would produce
  a lockfile that cannot install in CI.
- Both packages were installed locally and confirmed to resolve to the
  bumped versions in the actual tree (`npm ls`).
- Because these are transitive pins under `eslint`/`minimatch`, the
  functional risk is brace-expansion and YAML behaviour. Lint (which
  exercises minimatch globs), the full test suite, the standalone build
  and `scripts/validate-build.js` were all re-run against the bumped
  tree and are unchanged.
- `npm audit --package-lock-only --json` now reports zero findings.
- `node .security/scripts/audit-hash.js`, then
  `node .security/scripts/verify-audit.js`.

## Vulnerability Findings

(one of which the upstream advisory itself rated moderate).

### On reachability, recorded so the next alert is calibrated

Both advisories are CPU-exhaustion (CWE-400/407) classes. Their
reachable surface here is a developer running `npm run lint` against a
malicious ignore glob or YAML config. They are **not** reachable from
the shipped HTML, from any user-facing input, or from the network. This
release closes them for hygiene and so that the next audit starts from a
clean baseline rather than a standing two.
