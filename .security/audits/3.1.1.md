## Methodology

- `npm audit --package-lock-only --json` run against the committed
  lockfile before and after the change, and against `main` for comparison.
- Lockfile regenerated in a linux/amd64 environment (the repo pins
  `@rolldown/binding-linux-x64-gnu` as a devDependency, so a macOS/arm64
  host cannot resolve it).
- Full test suite executed on the new dependency tree under Node 22 and,
  separately, under Node 20.13 to check the engine floor in the CI matrix.
- Lint, standalone build, and bundle size re-run.
- `SECURITY.md` claims re-checked: this release touches no runtime code
  path, so every claim carries forward from v3.1.0 unchanged.

## Vulnerability Findings

No new findings in application code. One supply-chain observation:

### F-001 — `vitest` declared engine floor is lower than its dependency tree

- **Severity:** informational
- **Category:** dependency
- **Location:** `package.json:26`
- **Description:** `vitest@5` declares `engines.node: ^22.12.0 || ^24.0.0 || >=26.0.0`,
  while CI's matrix still includes Node 20.13. The suite runs and passes on
  20.13 anyway, so this is a declared-support mismatch rather than a
  functional break.
- **Impact:** Testing on a Node version the tooling does not claim to
  support. No effect on the shipped artifact — `vitest` is a devDependency
  and is never bundled.
- **Remediation:** Raise the CI matrix floor to 22.x.
- **Status:** accepted — see Accepted Risks.

Before (dependabot's original `vitest@^5.0.0` bump, and `main`):


Advisories: `@vitest/mocker`, `vitest`, `vite`, `source-map-js`,
`brace-expansion`, `js-yaml`.

The initial dependabot change pinned `vitest@^5.0.0`, which still fell
inside the affected ranges for two `@vitest/mocker` advisories:

- GHSA-qxg6-89mg-rqv8 — code injection via unauthenticated manual mock
  registration (`>=5.0.0-beta.1 <5.0.3`)
- GHSA-xp26-3454-mjgp — Windows backslash traversal bypassing the mocker
  redirect allowlist (`>=5.0.0-rc.2 <5.0.3`)

This release therefore moves to `vitest@^5.0.5`, which resolves both.

After:

```
{ "info": 0, "low": 0, "moderate": 0, "high": 2, "critical": 0, "total": 2 }
```

| Package | Severity | Direct | Range | Reached from |

| `js-yaml` | high | no | `>=4.0.0 <4.3.2` | `@eslint/eslintrc` ← `eslint` |

fixed releases and i18n infrastructure work; tracked separately rather
than bundled into a dependency patch.
