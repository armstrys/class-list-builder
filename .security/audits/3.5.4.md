## Scope

Single-file React SPA distributed as a standalone HTML bundle, plus its
build pipeline and the public security claims in `SECURITY.md`.

Paths covered by the manifest hash:

- `src/**`
- `package.json`, `package-lock.json`
- `SECURITY.md`
- `build-standalone.js`, `class-list-builder-source.html`,
  `scripts/validate-build.js`

Out of scope: `node_modules/` (covered transitively via `npm audit`),
`tests/**`, developer-only scripts not in the manifest.

This release is a bug sweep, not a feature: seven filed defects, one commit
each, shipped together. The manifest-covered changes are
`src/optimizer.js` (every balance baseline now derives from placed students),
`src/utils/assessment.js` (baselines scored on the same set; per-class category
statistics), `src/components/OptimizePage.js` (two effect dependency arrays, an
unplaced-students pool, the count beside the balance score and its live-region
announcement), `src/components/StudentCard.js` and
`src/components/StudentDetailModal.js` (an `unplaced` variant that carries no
lock control), `src/components/AssessmentModal.js` (renders the category
statistics), `src/components/SetupPage.js` (passes category criteria to the
student CSV export), `src/styles.css` (pool layout), and the 3.5.4 patch
version bump. The audit is diff-focused: the touched modules were re-read in
full, and the unchanged tree relies on the v3.5.3 audit.

One non-source file changed: `.gitignore` now ignores `node_modules` without a
trailing slash. The directory form did not match a *symlink* named
`node_modules`, and an intermediate commit on this branch had tracked one (a
worktree symlink to another checkout). It was removed before this branch was
handed over and never reached `main`; the ignore rule change is what stops it
recurring. `.gitignore` is not in the manifest, so no hash moves.

## Vulnerability Findings

No security findings of severity low or above.

The change is small but it touches three boundaries where a defect would be a
real finding, so each was checked explicitly:

**The drag-and-drop payload is not trusted, and cannot name a destination.**
`handleDrop(e, classIdx)` reads only a student id from
`dataTransfer.getData('text/plain')`; the destination class index comes from
the rendered column that received the drop, never from the payload
(`src/components/OptimizePage.js:193-195`). No `File`, `DataTransferItem`, or
URL is read anywhere in the path — the handler never calls `getAsString`,
`files`, or `types`. A crafted payload can at most name an id, and
`moveStudent` writes `assignment[id] = classIdx` in local state. Nothing is
executed, fetched, or written to storage.

**Category values reach a spreadsheet through the existing escaping path.**
#107 widens which columns the *student* backup export carries: category
criteria now produce columns there as they already did in the class-lists
export. Both go through `escapeCSVValue`, which prefixes a leading `=`, `+`,
`-`, `@`, tab or carriage return with a single quote before RFC 4180 quoting
(`src/csv.js:8-19`, the F-005 remediation from v2.0.0). Cell values are
user-typed student data that the app already exported elsewhere; the change
adds no new sink and no new escaping requirement, and a student name that
reads as a formula is defused by the same function.

**The new arithmetic cannot divide by zero or paint `NaN`.** Moving every
baseline from the roster to `classes.flat()` means the population count can be
zero — an empty board, or a roster where nothing is placed. Every derived
statistic in `computeCostTerms` and in the optimizer's `costFromSums` /
`swapDelta` is guarded by a `placedCount ? … : 0` or `numClasses` denominator,
`meanSize` is `placedCount / numClasses`, and `tests/cost-breakdown.test.js`
asserts that a nothing-placed call returns finite zeros and that the reported
score is `0`, not a perfect score. `src/utils/assessment.js` scores both
baselines on the same placed-students set for the same reason: a baseline of
`0` against a current cost of `0` previously fell through to the defensive
floor and displayed 100 for an empty board.

**The pool is presentation over existing state.** `src/components/StudentCard.js`
renders text nodes and inline `style` objects built from numbers; there is no
`dangerouslySetInnerHTML`, `innerHTML`, `eval`, or `new Function` anywhere in
`src/` (grep returns no matches). The new region's accessible name is a
template over a count (`${unplaced.length} student…`), and the only new
user-facing string that is not a literal is the student's own name, which
already reached the DOM the same way in the columns.

For completeness, the standing informational notes still hold against this
tree: no inline `on*=` handlers in the built artifact; no student data in
localStorage; no network calls in `src/`; no `console.log` in `src/`
(`tests/no-debug-output.test.js` now enforces that, and it is the test that
retired the debug logging removed in #109).
