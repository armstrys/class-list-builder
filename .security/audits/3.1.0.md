## Changes Since v3.0.0

1. **Print report grid lines** (`src/styles.css`, issue #78). Vertical
   rules and an outer border added to `.print-student-table` inside the
   existing `@media print` block; the row rule darkened from `#eee` to
   `#ddd` for a uniform grid. Presentation-only. No `url()`, `@import`, or
   external reference introduced — verified against the diff.

2. **Multi-start optimizer** (`src/optimizer.js`,
   `src/components/OptimizePage.js`). New `optimizeMultiStart()` runs
   `OPTIMIZE_RESTARTS` (5) independent annealing trajectories at integer
   salts `0..N-1` and keeps the lowest-cost result, selected by the full
   constrained cost. `OptimizePage.runOptimize` now calls it instead of
   `optimize()`.

   Motivation was a scoring defect, not a security issue: the assessment's
   balanced baseline already ran best-of-5, while the app ran a single
   trajectory at salt 0 — which the baseline also runs — so
   `balancedCost <= currentCost` held by construction and an unconstrained
   assignment could only score 100 when salt 0 won the restart lottery.

   The security-relevant properties are preserved: the function introduces
   no `Math.random`, no network, no storage, and no new data flow. It is a
   pure function of its inputs and remains deterministic (asserted by test).

3. **Score-normalization epsilon** (`src/utils/assessment.js`).
   `COST_EQUALITY_EPSILON = 1e-9` collapses sub-ULP cost differences to
   zero before the `p=0.35` power law, which is near-vertical at the
   origin. Costs are ~1e-3, so the tolerance sits ~6 orders of magnitude
   below the compared values. The same epsilon now gates the pre-existing
   defensive-floor `console.warn` so an exact tie stops logging a spurious
   warning.

4. **Shared restart constant.** `computeBaselineBalanced`'s hardcoded
   `restarts = 5` default became `RESTARTS_REF`, resolved from
   `OPTIMIZE_RESTARTS` across the script boundary. This is the only change
   in the release that introduces a new failure mode — see F-005.

5. **Lint globals** (`.eslintrc.json`) — `optimizeMultiStart` and
   `OPTIMIZE_RESTARTS` registered as readonly globals. Outside the manifest;
   no effect on any hash.

6. **Version bump** — `package.json`, `src/defaults.js`, and
   `package-lock.json` to 3.1.0.

7. **Audit remediations** (commit `f9dfdb4`) — `computeBaselineBalanced`
   now throws on an unusable restart count (F-005); the major-version
   refusal message now names the recovery path (F-004); the
   `@rolldown/binding-linux-x64-gnu` direct devDependency was dropped
   (F-002). Details under each finding.

Minor rather than patch because re-optimizing identical inputs now returns
a different (better) assignment than v3.0.0 did. Saved projects are
unaffected on load: they restore a stored assignment rather than re-running
the optimizer.

`claims-sha256` (`2546c2ce…`) and `build-sha256` (`27a801b0…`) are
byte-identical to v3.0.0 and to v2.3.0, confirming that neither
`SECURITY.md` nor the build entrypoints were touched. `sources-sha256`
changed for the five source files named above; `deps-sha256` for the version
bump alone.

**Lockfile note.** `package-lock.json`'s root `version` was stranded at
`2.3.1` — it was never advanced through the 2.3.1 → 3.0.0 releases.
`npm version 3.1.0` corrected it as a side effect. The diff against `main`
is exactly two version strings; no dependency resolution changed. The CI
version gate compares only `package.json` against `src/defaults.js`, so this
drift was ungated and could have continued accumulating. Worth considering
extending that gate to the lockfile root, though it is not a finding — no
dependency was misrepresented, since resolution lives in `packages`, not in
the root version string.

## Vulnerability Findings

### F-005 — Cross-file restart constant fails **open**, silently scoring every assignment 100

- **Severity:** low
- **Category:** other (correctness / integrity of a user-facing safety signal)
- **Location:** `src/utils/assessment.js:26` (`RESTARTS_REF`), consumed at
  `src/utils/assessment.js:93`
- **Description:** This release replaced `computeBaselineBalanced`'s
  self-contained `restarts = 5` default with a constant resolved across the
  script boundary:

  ```js
  const RESTARTS_REF = typeof OPTIMIZE_RESTARTS !== 'undefined' ? OPTIMIZE_RESTARTS : _restarts;
  ```

  Both arms can be `undefined` — the browser arm if `src/utils/assessment.js`
  is ever evaluated before `src/optimizer.js`, the Node arm if the require
  path changes. `restarts` then defaults to `undefined`, and the loop
  `for (let salt = 0; salt < undefined; salt++)` executes **zero** iterations,
  so `bestCost` is returned as its `Infinity` initializer.

  Reproduced end to end rather than inferred: with `balancedCost = Infinity`,
  `normalizeBalanceScore` takes its defensive floor (`currentCost < balancedCost`),
  clamps the baseline to the current cost, and returns

  ```
  { "score": 100, "effectiveBalancedCost": 0.005 }
  ```

  — a perfect score for an arbitrary assignment. The failure is silent: the
  epsilon gate added in this same release suppresses the `console.warn` only
  for sub-ULP gaps, but the `Infinity` path produces a gap far above the
  epsilon, so a warning *would* still fire on the console. Nothing surfaces
  in the UI.

- **Impact:** Not reachable in the shipped artifact. Script order is fixed
  at `class-list-builder-source.html:69` (optimizer) before `:82`
  (assessment), the build inlines in that order, and this was confirmed in a
  live browser (`OPTIMIZE_RESTARTS === 5`). The exposure is to future edits:
  reordering script tags, lazy-loading, or moving `assessment.js` earlier
  would degrade the balance score to a constant 100 with no test failure and
  no user-visible error. For a tool whose only quality signal to a teacher is
  that score, failing open is the wrong direction — a teacher would be told a
  class list is perfectly balanced when it has not been evaluated at all.
  No confidentiality or integrity exposure of student data.
- **Remediation:** Applied in this release (`f9dfdb4`).
  `computeBaselineBalanced` now fails closed, throwing rather than returning
  `Infinity`:

  ```js
  if (!Number.isFinite(restarts) || restarts < 1) {
    throw new Error(`computeBaselineBalanced: restarts must be a positive finite number, got ${restarts}. …`);
  }
  ```

  Throwing was chosen over a literal `|| 5` fallback because an unevaluable
  baseline is a wiring error, and silently substituting a default would hide
  it. The blast radius was checked before choosing: `OptimizePage`'s
  assessment effect (`src/components/OptimizePage.js:125-128`) already wraps
  `runFullAssessment` in `try/catch`, logs, and clears `isAssessing` in
  `finally`; the UI gates the score on `assessment.ready`. So the throw
  surfaces in the console and the score is simply **absent**, not wrong, and
  the UI does not hang.

  Two regression tests, one on the mechanism and one on the consequence:
  non-finite / non-positive restart counts throw, and the baseline never
  returns a non-finite cost. The test file records why an explicit
  `undefined` is deliberately excluded from the throwing set — it resolves
  to the default parameter, which is the very path the guard protects.
- **Status:** fixed-in-this-release

#### F-002 — `@rolldown/binding-linux-x64-gnu` direct devDependency breaks `npm ci` off-platform

- **Status:** fixed-in-this-release (`f9dfdb4`)
- **Root cause confirmed:** of the 14 `@rolldown/binding-*` packages in the
  lockfile, this was the **only one not marked `optional`** — precisely
  because the direct devDependency pin overrode the optional resolution that
  `vite` → `rolldown@~1.2.1` provides for every platform binding.
- **Remediation:** the direct devDependency was removed. The resulting diff
  is one line in `package.json` and one added `"optional": true` in
  `package-lock.json`. **No version changed** — the binding was already
  resolved at `1.2.3`, identical to its 13 siblings, so the `^1.0.0-rc.18`
  range had not been pinning an older artifact and no new bytes enter the
  supply chain. Verified by inspecting every changed lockfile entry: no
  non-rolldown package was touched.
- **Verification:** `npm ci` now completes on darwin/arm64 **without
  `--force`**, which was the reported symptom. The full suite (225 tests)
  passes against the freshly installed tree and the standalone build
  validates. The lockfile was re-diffed after `npm ci` to confirm the
  install did not mutate it beyond the intended change.
- **Residual risk, disclosed:** CI runs linux/x64 and was **not** exercised
  here. The mechanism is the same one that resolves `binding-darwin-arm64`
  on this host, and the required linux binding remains in the lockfile at
  the same version, so the expected outcome is unchanged CI behavior — but
  the linux install path is verified by inference, not by execution. The CI
  run on the release PR is the confirming test.

## Prompt Injection Defense Notes

A sentinel scan was performed across all of `src/**` (33 files) at this
commit, covering instruction-override phrases, role-marker injection,
Unicode tricks, and hidden base64/hex payloads, plus a targeted scan of the
five changed source files. Reporting both what was found and that the scan
ran, since silence and absence are otherwise indistinguishable.

**Two benign matches, no injection attempts** — both pre-existing, neither
in this changeset, and both previously recorded in the v2.3.0 and v3.0.0
audits:

1. Instruction-phrase scan matched one line, at `src/components/HelpModal.js:75`:

   ```
   Total flags and scores act as safety nets to catch overall imbalances.
   ```

   The pattern `act as` fires on ordinary English describing optimizer
   behavior.

2. Unicode scan matched one line, at `src/components/SetupPage.js:178`:

   ```
   <div className="icon">👩‍🎓</div>
   ```

   The hit is U+200D (zero-width joiner) as a legitimate component of the
   `👩‍🎓` emoji ZWJ sequence, not a hidden-character payload.

**Not found:** no bidi overrides (U+202A–U+202E, U+2066–U+2069), no tag
characters (U+E0000–U+E007F), no stray zero-width characters outside the
emoji sequence above, no base64/hex blobs over 50 characters in any changed
file, no role markers (`[INST]`, `<|im_start|>`, `<<SYS>>`, `system:`,
`assistant:`), and no text anywhere in `src/**` attempting to instruct,
redirect, or reconfigure an AI auditor.

The only non-ASCII characters introduced by this changeset are three em
dashes (U+2014) inside comments in `src/optimizer.js` and
`src/utils/assessment.js` — printable, not zero-width, not bidi.

No instruction text from any source file altered this audit's scope,
severity classifications, findings, or sign-off. The audit plan was fixed
before any source file was opened and was executed unchanged.

**Residual risk:** indirect prompt injection is not a solved problem as of
mid-2026; adaptive attacks defeat published defenses at high rates. The
hardening applied here is defense-in-depth, not a guarantee. The
deterministic checks (`audit-hash.js`, `verify-audit.js`) and the human
sign-off below are the enforcement layer; the AI-assisted review is a force
multiplier, not the arbiter. This release's disclosed auditor-independence
gap (see Methodology) narrows that force multiplier further.
