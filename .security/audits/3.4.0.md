# Security Audit — v3.4.0

## Scope

Single-file React SPA distributed as a standalone HTML bundle, plus its
build pipeline and the public security claims in `SECURITY.md`.

Paths covered by the manifest hash:

- `src/**` (34 files)
- `package.json`, `package-lock.json`
- `SECURITY.md`
- `build-standalone.js`, `class-list-builder-source.html`,
  `scripts/validate-build.js`

Out of scope: `node_modules/` (covered transitively via `npm audit`),
`tests/**`, developer-only scripts not in the manifest, and
`README.md` / `PRODUCT.md` / `DESIGN.md` / `.impeccable/design.json`.

Predecessor: v3.3.2.

**Nature of this release:** one new user-facing surface (a guided tour), a CSV
template download helper, and the removal of the build-time welcome flag in
favour of one persisted UI-preference key. No new runtime dependency, no
network call, no student data stored, no change to the optimizer, the CSV
parser, or the project serialization format.

The welcome screen previously appeared only in the hosted build, gated on a
`window.SHOW_WELCOME_MODAL` script injected by the Pages workflow. That is now
`localStorage['clb-welcome-seen']`, so the hosted build and the downloaded
standalone file behave identically and nothing is injected per deploy. The
injected `<script>` was a `sed` rewrite of the release artifact; removing it
shrinks the gap between the audited artifact and the deployed one.

## Vulnerability Findings

No security findings.

The one new input surface is the CSV template download. It is a *producer*, not
a consumer: it builds a two-line sheet from the criteria labels the user already
controls, and passes every cell through the existing `escapeCSVValue`, which
already defuses spreadsheet formula injection (`=`, `+`, `-`, `@`, tab, CR get a
leading single quote; see `.security/audits/2.0.0.md` F-005). Because the
criterion *labels* flow into that helper, a label beginning with `=` cannot
become a live formula in the downloaded file.

The tour renders step copy and a step title — both hard-coded constants in
`src/components/Tour.js` — through React text interpolation. No user data is
interpolated into the tour, and the one DOM operation it performs
(`classList.add`/`remove` on a `[data-tour="…"]` match) takes its selector from
the same hard-coded table, never from input.

The welcome gate reads `localStorage['clb-welcome-seen']` and compares it to
`'1'`. It is not a security boundary and is not treated as one: it controls
whether a splash screen renders, nothing else. Both the read and the write are
wrapped in `try`/`catch`, consistent with the existing theme key.

For completeness, the two informational findings from v3.3.0 remain accurate
against the current tree: values are rendered only through React text
interpolation (no `dangerouslySetInnerHTML` / `innerHTML` / `eval` /
`new Function` anywhere in `src/`), and no student data is written to
localStorage.
