### F-003 (from the v3.0.0 audit) — resolution

- **Original finding:** `2.3.0.md`'s Accepted Risks table describes
  CLB-EXC-0001 as `'unsafe-eval'` in CSP and CLB-EXC-0002 as
  `'unsafe-inline'` in CSP `style-src`. The registry defines them as
  *"Single maintainer — no separation of duties"* and *"ExcelJS 4.4.0
  transitive CVEs in Node-only code paths"*.
- **Root cause established:** the audit misdescribed the IDs; the registry
  was **not** rewritten afterwards. At the audited commit `e82e633`,
  `exceptions.json` already read:

  ```
  CLB-EXC-0001 | Single maintainer — no separation of duties
  CLB-EXC-0002 | ExcelJS 4.4.0 transitive CVEs in Node-only code paths
  ```

  The registry has carried those two definitions since `f7c4027` (the Tier 2
  migration) and no ID has been reused. This distinction matters: exception-ID
  reuse would have been a genuine integrity problem in the audit chain,
  whereas a mislabelled table is a documentation defect confined to one file.
- **Contributing factor, recorded for the trail:** `2.3.0.md` was produced by
  a different assistant and skill (`.opencode/skills/security-audit`,
  `hf:moonshotai/Kimi-K2.6`) than the one used from v3.0.0 onward. The two
  risks it named — `'unsafe-eval'` and `'unsafe-inline'` — are both real
  properties of this project's CSP and are documented in `SECURITY.md`; they
  simply are not what those exception IDs cover, and neither requires an
  exception entry.
- **Status:** fixed-in-this-revision.
