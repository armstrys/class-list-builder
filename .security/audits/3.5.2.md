# Security Audit — v3.5.2

## Scope

Single-file React SPA distributed as a standalone HTML bundle, plus its
build pipeline and the public security claims in `SECURITY.md`.

Paths covered by the manifest hash:

- `src/**`
- `package.json`, `package-lock.json`
- `SECURITY.md`
- `build-standalone.js`, `class-list-builder-source.html`,
  `scripts/validate-build.js`

Out of scope: `node_modules/` (covered transitively via `npm audit`),
`tests/**`, developer-only scripts not in the manifest. This release also adds
`.github/ISSUE_TEMPLATE/bug_report.yml`, which is outside the manifest (GitHub
renders it, the app never ships it) and is discussed under Data Handling below.

## Methodology

- `npm audit --json` reviewed against the current lockfile; summary below.
- The full diff read, then the touched modules re-read in their entirety
  (`src/components/Tour.js`, `src/app.js`, `src/components/SetupPage.js`,
  `src/components/WelcomeModal.js`), not just the changed hunks.
- Every claim in `SECURITY.md` verified by command or by reading the cited
  code path; results recorded in the table below.
- The release artifact was built and inspected: remote resource loads, outbound
  anchors and their `rel`/`target`, inline event handlers, CSP bytes.
- Behavioural verification in WebKit (Safari's engine) and Chromium on the
  change this release is about, because the defect being fixed was
  engine-specific and a Chromium-only pass would have certified a broken claim.
- Sentinel scan of the changed files for text addressed to an AI auditor.

## Vulnerability Findings

No security findings of severity low or above.

Three things are worth stating explicitly, because a diff-reader could
otherwise read them as security-relevant:

**The release gains outbound hyperlinks, not outbound requests.** `src/app.js`
adds one `target="_blank"` anchor to the project's repository, and
`src/components/WelcomeModal.js` gains two more (project page, issue form). All
five outbound anchors in the artifact — three pre-existing — were checked
individually: every one carries `rel="noopener noreferrer"`, so the new tab
gets no `window.opener` handle back into the app and the app's URL is not sent
as a `Referer`. The `href`s are compile-time constants; no student data, project
state, or identifier is appended to them. Clicking a link is a user-initiated
navigation and transmits nothing that a text editor opening the same file
would not.

**No user-controlled value reaches a new sink.** The scrim rewrite in
`src/components/Tour.js` builds a `clip-path: path(…)` string, and a CSS
injection there would be a real finding, so it was traced: the only inputs are
`getBoundingClientRect()` numbers and `innerWidth`/`innerHeight`
(`Tour.js:71-96`). They are interpolated as JavaScript numbers — no user text,
storage value, or URL parameter can reach the string. The step's target name
still comes from the module-constant `TOUR_STEPS`, so the `querySelectorAll` can
only ever match that fixed list.

**The element-name and attribute change is not a privilege change.** The scrim
element changed from a hole-sized box to a full-viewport element with a cut-out.
It remains `pointer-events: none` and below the callout in z-order; the tour
still does not block the control it points at, and nothing became newly
clickable or newly covered in the DOM sense.

Not a security issue, recorded because it was found during this audit and shows
the verification was not theoretical: the first version of the scrim fix used
`path("evenodd, …")`, which is invalid CSS. WebKit dropped the declaration
silently and left `clip-path: none`, dimming the very control the tour pointed
at, while `CSS.supports()` reported support. Corrected to
`path(evenodd, "…")` and covered by a test that asserts the fill rule is a
`path()` argument rather than part of the path data.

Also for completeness, the standing informational notes still hold against this
tree: no `dangerouslySetInnerHTML` / `innerHTML` / `eval` / `new Function`
anywhere in `src/` (grep returns no matches); no inline `on*=` handlers in the
built artifact; no student data in localStorage.

No prompt-injection attempts observed. The change is four components, a
stylesheet, a contributing guide section, a security-document correction, an

manifest-covered tree from an untrusted source.

policy addressed to humans ("the signature is yours, not the model's",
"Required sections are present"). Those were treated as data. They are also the
reason this document does not claim the AI signed it.

## Data Handling Note (issue template)

`.github/ISSUE_TEMPLATE/bug_report.yml` is new and is the only change in this
release that touches how data could leave a user's machine: it is the text a
teacher reads when they click the help link, so it asks for a browser name and
a description and states plainly not to paste student names, IDs, or a real
roster, and to crop screenshots. It reduces the chance that a bug report
carries FERPA-regulated data into a public issue tracker. It is outside the
manifest, is never shipped to users, and adds no code to the app.
