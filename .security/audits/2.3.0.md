# Security Audit — v2.3.0

## Scope

Single-file React SPA distributed as a standalone HTML bundle, plus its
build pipeline and the public security claims in `SECURITY.md`.

Paths covered by the manifest hash:

- `src/**` (32 files)
- `package.json`, `package-lock.json`
- `SECURITY.md`
- `build-standalone.js`, `class-list-builder-source.html`,
  `scripts/validate-build.js`

Out of scope: `node_modules/` (covered transitively via `npm audit`),
`tests/**`, developer-only scripts not in the manifest.

## Methodology

- `npm audit --json` reviewed; zero vulnerabilities found.
- Source tree read end-to-end with prompt-injection-hardened skill.
- Each claim in `SECURITY.md` verified against current source.
- Changed files reviewed in depth: `OptimizePage.js`, `sample-data.js`,
  `app.js`, `SetupPage.js`, `styles.css`, `.eslintrc.json`, `README.md`,
  `CONTRIBUTING.md`.

## Changes Since v2.2.2

This release introduces UI and sample-data changes:

1. **Toolbar redesign** — restructured the optimize page toolbar to prevent
   overflow. Removed Lock All button, converted Undo/Redo to icon buttons,
   made violations badge always visible, moved Save Lists/Print Report back
   to visible buttons, kept only Unlock All in a dropdown.
2. **Violations badge always visible** — shows "✓ All constraints met" in
   green when satisfied, "⚠️ N" in red with violations. Tooltip shows
   per-constraint breakdown.
3. **Sample constraint generation** — new `generateSampleConstraints()`
   function creates random non-conflicting constraints for demo/sample data.
4. **Documentation updates** — README and CONTRIBUTING.md updated to reflect
   UI changes.

## Vulnerability Findings

No findings.

The `Math.random()` usage in `generateSampleConstraints()` (via `rnd()`
and `shuffleArray()`) is informational only — sample/demo data generation
does not require cryptographic randomness or determinism. The optimizer
itself continues to use its seeded RNG for reproducible results.
