## Scope

Single-file React SPA distributed as a standalone HTML bundle, plus its
build pipeline and the public security claims in `SECURITY.md`.

- `src/**` (32 files; +1 from v2.1.0 — the new `PrintReportView.js`)

This release supersedes the v2.1.0 audit (`.security/audits/2.1.0.md`).

Changes from v2.1.0:

1. **PDF class list print report** — a new browser-print feature.
   - New component [`src/components/PrintReportView.js`](../../src/components/PrintReportView.js)
     renders a print-only DOM via `ReactDOM.createPortal(..., document.body)`.
     One cover page (class overview table + constraints listing) and one page
     per class (header, stats badges, student table, gender footer).
   - New pure data builder `buildPrintReportData()` in
     [`src/defaults.js:93-176`](../../src/defaults.js#L93-L176) — transforms
     existing in-memory state into the structured report.
   - New `@media print` block in
     [`src/styles.css:621-852`](../../src/styles.css#L621-L852) — hides
     screen UI with `body > *:not(#print-report) { display: none }`, forces
     light-mode CSS vars inside `#print-report`, sets
     `print-color-adjust: exact`, and uses `page-break-before: always` on
     subsequent class pages. Density tiers (`--dense` at 19+ students,
     `--ultra` at 26+) shrink the table font and padding so larger classes
     fit on one printed page.
2. **Print button in OptimizePage** —
   [`src/components/OptimizePage.js:279-285`](../../src/components/OptimizePage.js#L279-L285)
   adds a "🖨 Print Report" button that calls `window.print()`, gated on
   the optimization assignment being non-empty.
3. **Browser UI gender additions** (no print impact, no security surface) —
   `StatsStrip` adds Male/Female bar groups
   ([`src/components/StatsStrip.js:22-32`](../../src/components/StatsStrip.js#L22-L32));
   `ClassColumn` adds M/F/U badge pills to each class footer
   ([`src/components/ClassColumn.js:57-59,113-117`](../../src/components/ClassColumn.js#L113-L117)).
4. **`generateColor` gains an optional `theme` parameter**
   ([`src/defaults.js:51-71`](../../src/defaults.js#L51-L71)) so the print
   path can force light-mode colors regardless of the app's current theme.
5. **HTML wiring** — one new `<script>` tag in `class-list-builder-source.html`
   loading `PrintReportView.js`. No new external resources.
6. **Version bump** — `package.json` and `src/defaults.js` to 2.2.0.

SECURITY.md was not modified for this release; `claims-sha256` is
identical to v2.1.0's, confirming the public claim surface is unchanged.

## Vulnerability Findings

No findings.

The PDF print report is a pure rendering layer over existing in-memory
state. Source review identified:

- No new network behavior
- No new persistence (no localStorage / IndexedDB / cookies / file writes)
- No new injection sinks — all user data (student names, teacher names,
  criterion labels) flows through JSX text nodes, which React escapes
- No new dynamic code execution (`eval`, `new Function`,
  `dangerouslySetInnerHTML`)
- No new supply-chain footprint (one new local script, zero new external URLs)
- The `ReactDOM.createPortal(..., document.body)` portal target is a
  constant DOM node, not user-controlled
- The `window.print()` invocation is a browser-native API; output goes
  to the user's local print pipeline by their explicit action

### Informational notes (not findings)

- **INFO-2.2.0-A.** [`src/components/PrintReportView.js:207`](../../src/components/PrintReportView.js#L207)
  builds a className via template literal: `` `badge badge-${s.gender || 'U'}` ``.
  The `gender` field is constrained to `'M'`, `'F'`, or `'U'` by the
  form's `<select>` ([`StudentFormModal.js:49-52`](../../src/components/StudentFormModal.js#L49-L52))
  and by the CSV import normalization ([`csv.js:55`](../../src/csv.js#L55)),
  and there is no other write path. Even if a value outside that set
  reached this line (e.g., from a hand-edited project JSON), the worst
  case is a non-matching CSS class string — not a script execution
  vector. `className` is assigned as a string property by React, not
  parsed as HTML. No security impact; flagged as a robustness note for
  any future code that consumes `gender` more permissively.
- **INFO-2.2.0-B.** The new `@media print` block uses
  `print-color-adjust: exact` to force background colors (notably the
  per-flag dot colors and the dark-mode-overridden badge palette) into
  the printed output. This is a user-visible behavior change in the
  printed artifact — the report now prints in light-mode palette
  regardless of the app's current theme — but has no security impact.
